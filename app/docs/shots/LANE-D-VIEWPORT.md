# Lane D: the viewport

**Seat:** Metis. **Code:** `app/Sources/ConceptStudio/Shots/Viewport/`,
`app/Tests/ConceptStudioTests/Shots/Viewport*.swift`. **Machine:** a Mac with Xcode (RealityKit).

**Mission.** The 3D view where blocking happens, and the shot camera view. This lane builds:
- an editor camera;
- RealityKit display through Lane B's scene mapper;
- overlays: marks, path ribbons, the camera body and the selection;
- picking and tools: select, place asset, drop marks;
- move and rotate handles;
- the look-through view, rendered by the export renderer;
- the viewport's keyboard and VoiceOver support.

This is the hardest lane, because it carries the interaction feel. Build the logic so it can be tested
without a window. Lane C hosts your two views from C1 (day 1), so your work shows in the app as soon as it
merges.

## Architecture inside the lane

This is a recommendation; the lane owns the choice.

- **`EditorCamera`** is a pure value: target, distance, yaw and pitch for orbit, pan and dolly. It produces
  a `CameraFrame` through `CameraFrame.make(…, aspect:)` for the viewport's own `PixelSize`, which can be
  any size.
  - That frame places the RealityKit camera, via the mapper's `cameraEntity`.
  - It also makes picking rays, via `CameraFrame.ray(through:size:)`.
  - What you see and what you click come from one source. Don't use RealityKit's built-in camera
    controls; their camera can't be read back exactly.
- **Picking** runs on the CPU against the current `SceneFrame`. Transform the ray into each part's frame
  and test the part's local bounds. That gives an `EntityID` with no window, so tests are headless. Ground
  placement and dragging intersect the ray with y = 0.
- **Display:** a `RealityView` holding two roots:
  - the mapper's `root`, updated from `store.frame`;
  - the **overlay root** this lane owns: grid, spike-tape marks, ribbons from `evaluator.paths()`, the
    camera body and frustum, selection boxes, and handles.

  Export renders only the mapper's root, so editor chrome can't reach an exported pixel. Never tint the
  mapper's entities for selection; draw selection in the overlay.
- **Gestures** set `store.preview` while dragging, and call `store.run` once on mouse-up. `run` shows any
  error through the app's window alert.
- **`ShotCameraView`** asks `ShotFrameRenderer` for `store.frame` with `PrevisLook(scene:)`, letterboxed to
  the shot canvas. Rendering is coalesced: while a render is in flight, only the newest request is kept.
  It uses the same renderer and inputs as export, so preview matches export by construction.
- **Offscreen snapshots,** for tests and the status file, use
  `ShotFrameRenderer.image(of:look:camera:overlay:size:)` with the editor camera and a **clone** of the
  overlay root. Write them to the folder in `SHOTS_SNAPSHOT_DIR`, or a temp folder when it's unset. The
  status file says how to regenerate them; it never holds paths.
- **Tests use `twoPersonWalk(small: true)`** (22 frames, 320 × 576) to stay inside CI's time limit.
  Full-size snapshots are written only when `SHOTS_SNAPSHOT_DIR` is set.
- **Read-only.** When `store.isReadOnly` is true, the tools and handles are disabled, and selection and
  camera moves still work.

## Facts from the RealityKit probes

These were measured on macOS 27; their API annotations say macOS 15.
- **Available:** `RealityView`, entity gestures, `InputTargetComponent` with `CollisionComponent`,
  `unproject(…ontoPlane:)` and `Scene.raycast`. CPU picking makes the last few optional.
- **Not available on macOS:** `ManipulationComponent` (visionOS only). Handles are hand-built, and they are
  this lane's main work.
- **One camera:** `RealityView` has a single camera, which is why the look-through uses the offscreen
  renderer.
- **Post effects** (motion blur, depth of field, grain, HDR) must be off.
- **Main actor:** RealityKit types are `@MainActor`; keep geometry maths in plain values.
- **Single parent:** an `Entity` can have only one parent, so the renderer's `overlay` must be a clone.
- **Untested so far:** none of this has run on macOS 15 or inside the sandbox. Note any difference in the
  status file.
